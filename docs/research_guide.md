# Посібник: використання симулятора в університетській роботі

## Призначення

Використовуйте Quantum Laboratory як навчальний і чисельний стенд для перевірки наслідків ідеальної моделі двох спінів ½. Програма не є даними вимірювальної установки і не доводить нові фізичні ефекти.

## Рекомендована процедура

1. Сформулюйте передбачення до запуску: стан, операції, осі, статистику та критерій порівняння.
2. Зафіксуйте версію програми, залежностей, параметри, seed та всі фізичні припущення.
3. Порівняйте точні Born-імовірності з вибірковими частотами; оцініть статистичне відхилення та повторіть серію з кількома seed.
4. Для no-signaling порівнюйте розподіли локальних результатів B під різними невибірковими операціями A. Не умовлюйте B на окремий результат вимірювання A, якщо класичні дані A недоступні.
5. Для CHSH вкажіть чотири пари налаштувань, кількість спроб на пару, правило обробки невдалих/відсутніх подій і припущення. Цей застосунок не включає post-selection чи процедуру закриття loopholes.
6. Експортуйте JSON і CSV, додайте графіки PNG/SVG та збережіть конфігурацію. Переконайтеся, що версії, seed і кодова версія записані.
7. У методах роботи чітко відокремте аналітичні обчислення, випадкові вибірки і порівняння з реальними експериментами. Наведіть посилання з `scientific_model.md` і не приписуйте джерелам висновки, яких вони не містять.

## Мінімальні перевірки перед публікацією

- Запустіть `run_tests_windows.bat` на тому самому середовищі та збережіть лог.
- Перевірте trace=1, Hermiticity і невід’ємність власних значень матриці густини.
- Перевірте ізольовані стани, Bell-стани, одиничні обертання та межі ймовірностей.
- Звірте аналітичні кореляції для singlet з `E(a,b)=−a·b`.
- Проведіть convergence check за кількістю повторень і кількома seed.
- Якщо модель розширюється шумом, вимірювальним приладом або реальним Hamiltonian, додайте первинне джерело, явні одиниці, незалежні тести й документацію наближень перед використанням результатів.

## Як цитувати поточне програмне забезпечення

Зазначте назву Quantum Laboratory, версію з JSON-запису експерименту, дату доступу, параметри й seed. Додайте URL репозиторію, якщо він буде створений/опублікований. Не називайте симулятор валідованою моделлю реальної квантової точки.

## Stage 5A: N-спінова TFIM динаміка

Stage 5A підтримує ідеальний замкнений відкритий ланцюг із 2–6 спінів. Для відтворюваного початкового прикладу дивіться код у README: `N=3`, `|000⟩`, `J=1 s⁻¹`, `h=0.7 s⁻¹`, часова сітка `0…8 s`. Ці значення навчальні; вони не є калібруванням, оцінкою параметрів або підгонкою під Hensen. Застосовуйте ядро `run_tfim_experiment`, щоб модель, стани, часові ряди `mean_sigma_z` і `nearest_neighbor_zz`, метод solver та чисельна діагностика записувались через наявний формат JSON/CSV. Візуалізацію будуйте лише з повернених даних, не дублюючи фізичні обчислення у графічному шарі.

Перед інтерпретацією результату перевірте OBC список пар, Pauli-нормування, секунди та `s⁻¹`, початковий стан і версію коду з запису. Крокова оцінка похибки адаптивного solver є локальною; для наукової точності окремо повторіть траєкторію з жорсткішими `atol`/`rtol` і порівняйте фінальні стани/обсервабли, не покладайтеся лише на норму або унітарність. Для незалежної перевірки фізично тотожних систем можна використати окреме середовище, не додаючи QuSpin/QuTiP у runtime:

```powershell
py -3.13 -m venv .venv-stage5-validation
.venv-stage5-validation\Scripts\python.exe -m pip install -r requirements-stage5-validation.txt
.venv-stage5-validation\Scripts\python.exe scripts\validate_stage5_quspin.py --all
.venv-stage5-validation\Scripts\python.exe scripts\validate_stage5_qutip.py --fixture smooth-controls
```

Збережіть stdout повних validation-звітів і перевірте, що збігаються конвенція Паулі `±1`, одиниці, початковий стан, часові точки й саме відкритий список зв'язків. Окремий QuSpin periodic fixture перевіряє periodic модель та не підтверджує OBC результат. Фактичні порівняння й допустимі відхилення наведені у [звіті Stage 5A](stage5_validation.md); не переносіть їх на неперевірені розміри, параметри чи часові режими.

Stage 5A сам по собі не завершував Stage 5. Dynamic Quantum Receiver, Deviation Analyzer і перевірений експеримент Quantum Domino реалізовані на Stage 5B; Stage 5C UI та подальші погоджені компоненти залишаються попереду. Модель не є апаратною моделлю. Аналіз оригінальних даних Hensen залишається окремим і не використовується для підбору `J`, `h` чи допусків solver.

Після реалізації Stage 5B повну конфігурацію із JSON-запису можна відновити через `load_stage5b_configuration(path)` і повторно запустити через `run_stage5b_experiment`. Loader відновлює FieldSchedule, комплексні стани та frozen preregistration; confirmatory RNG seed читається лише з протоколу. Фактичний звіт і межі інтерпретації наведені у [Stage 5B results](stage5_validation.md#stage-5b-повторення-ізольованого-приймача).

## Stage 5B: приймач та статистичний аналіз

Публічний API `quantum_lab.run_dynamic_receiver_experiment` повертає повні стани A⊗R і редуковані receiver-стани для трьох сценаріїв. `run_stage5b_experiment` використовує те саме ядро, формує точні прогнози, plot-ready ряди й окремо виконує вибірковий аналіз лише за наявної заблокованої preregistration. Збережіть повні параметри, hash, raw outcomes та intervals за допомогою `save_stage5b_experiment`. Точні середні — це очікування багатьох повторних підготовок, не безперервний трек однієї системи.

Повторіть independent checks у вже створеному validation venv:

```powershell
.venv-stage5-validation\Scripts\python.exe scripts\validate_stage5b_qutip.py --all --output results\stage5b\validation_qutip.json
.venv-stage5-validation\Scripts\python.exe scripts\validate_stage5b_quspin.py --all --output results\stage5b\validation_quspin.json
```

Перед будь-якою confirmatory вибіркою зафіксуйте operator/site/time/pulse та statistical protocol; потужність має відповідати фактичним імовірностям і спільному reference. Після розкриття сценаріїв критерії не змінюються. Відсутність статистичної значущості обмежена інтервалом для обраної умови. Дивіться фактичні рахунки й CI у [Stage 5B validation report](stage5_validation.md#stage-5b-повторення-ізольованого-приймача). QuTiP і QuSpin залишаються тільки опційними незалежними інструментами, не runtime-залежностями.
