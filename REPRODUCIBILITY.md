# Quantum Laboratory: відтворюваність і релізний аудит

## Встановлення і запуск

Windows запуск: `start_windows.bat`. Скрипт встановлює Python залежності до `.venv`, виконує `npm ci` за lock-файлом, збирає Orbital Lab і запускає локальний API на виділеному ОС loopback-порту. Перед відкриттям браузера launcher перевіряє `/api/health` та HTML frontend; наявні зайняті порти не завершує. Для ручного запуску в розробницькому середовищі використовуйте локальний Python API і `frontend` Vite dev server з узгодженим proxy лише для розробки; релізний режим обслуговує зібраний frontend тим самим origin.

Поточний frontend API і наукове ядро мають loopback-only межу; дані лабораторії не надсилаються у зовнішній сервіс. Startup log розміщується у `%LOCALAPPDATA%\QuantumLaboratory\startup.log` (з fallback до системної тимчасової теки).

## Повторні перевірки

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv-stage5-validation\Scripts\python.exe scripts\validate_stage5b_quspin.py
.venv-stage5-validation\Scripts\python.exe scripts\validate_stage5b_qutip.py
cd frontend
npm ci
npm test
npm run build
```

QuTiP і QuSpin встановлюються в окреме тестове середовище, не є обов’язковими runtime-залежностями. Точні залежності UI зафіксовані у `frontend/package-lock.json`; Python runtime задається `pyproject.toml`, а фактичні версії для історичного Stage 5B запису вказані в його metadata. Фактичні результати останнього повного прогону наведено нижче.

## Межі відтворення

1. Перевірте точну версію Python, пакунків і Git revision; збережений Stage 5B запис має provenance поля та preregistration hash.
2. Перевірте SHA-256 джерельних архівів і вихідних файлів Hensen за manifest у `data/references/`.
3. Не змінюйте preregistration, протокол, random-stream design або критерії після розкриття вибірки. Повторний підтверджувальний тест потребує нової окремої вибірки і зафіксованих наперед критеріїв.
4. Валідаційні пороги порівнюйте на фізично еквівалентній нормалізації Паулі, тих самих одиницях, OBC та часовій сітці. Не застосовуйте періодичний QuSpin reference як OBC еталон.
5. Перевірки Stage 5B та Hensen є наявними записами. Не перегенеровуйте їх автоматично при звичайному запуску UI.

## Release audit, стан на 2026-10-21

- Робоче дерево має незакомічені й untracked зміни з Stage 5A/5B/5C; їх не можна трактувати як один перевірений релізний commit, комітити гуртом чи переписувати. Поточна робота не змінює Git history.
- Відсутній `LICENSE`/`NOTICE` з однозначною ліцензією самого проєкту. Знайдені сторонні залежності мають ліцензії в їхніх package metadata/файлах; це не надає ліцензії коду Quantum Laboratory.
- Авторів програмного забезпечення у репозиторії достовірно не ідентифіковано. Git-комітер не прирівнюється до автора. Тому `CITATION.cff` не заповнюється вигаданими особами або установою; до релізу потрібне підтвердження автора/авторів та бажаного способу attribution.
- Stage 5B запущено з вихідним кодом, що мав незакомічені зміни. Збережений provenance прямо це документує. Немає заднім числом створеного source snapshot, і цей аудит не змінює його checksum або історичний запис.
- `results/stage5b/` — дослідницькі provenance артефакти, їх потрібно включати до архіву релізу без редагування. `results/ui_experiments/` — локальні, користувацькі експорти; вони не повинні випадково стати частиною публікаційного commit.
- Build cache, локальні Python/Node середовища, pytest cache і тимчасові файли виключаються з version control правилами `.gitignore`.

## Безпечна процедура release candidate

1. Зробити резервну копію dirty checkout та зафіксувати повний `git status` і hashes без очищення.
2. Створити ізольований worktree/branch від узгодженої бази. Перенести лише конкретно перевірені файли й provenance-артефакти, залишивши історію Stage 5B без змін.
3. Власники підтверджують авторів, вибирають ліцензію коду й погоджують розповсюдження кожного набору/запису та сторонніх assets. Потім додати вірні `CITATION.cff`, `LICENSE`, notices і third-party license inventory.
4. Повторити повні тести у чистому середовищі, створити source archive, обчислити hashes і вручну переглянути staging diff.
5. Підготувати release candidate локально для перевірки. Не публікувати його та не створювати release tag без окремої явної інструкції.

## Зовнішні залежності й ліцензії

За lock-файлом UI основні пакети: React/React DOM 19.3.1 (MIT), Three.js 0.179.1 (MIT), React Three Fiber 9.8.2 (MIT), Drei 10.7.9 (MIT), Vite 7.3.7 (MIT), TypeScript 5.9.3 (Apache-2.0), Vitest 4.1.12 (MIT), Lucide React 0.468.0 (ISC). Точний повний npm граф залежностей і їхні metadata записані у lock-файлі; релізний bundle потребує third-party notice review. У Python runtime закріплені numpy 2.5.3, streamlit 1.65.0, plotly 6.9.0, kaleido 1.5.0 і matplotlib 3.11.2; середовище незалежної валідації має QuTiP 5.3.0, QuSpin 1.0.1, NumPy 2.5.4 і SciPy 1.18.1. Для кількох Python пакетів стандартизовані license classifiers відсутні в wheel metadata; перевіряти слід повні включені LICENSE файли відповідних distribution, а не виводити SPDX лише з порожнього metadata поля.

Ліцензійний статус проєктного коду залишається невстановленим, тому релізний артефакт поки що не готовий до публічного поширення.

## Фактична перевірка Stage 5C, 2026-10-21

- На попередньому checkpoint повний набір Python мав **184/184 тести**; актуальний повний прогін наведений у фінальному додатку нижче.
- Незалежні Stage 5B validators: QuTiP 5.3.0 і QuSpin 1.0.1 обидва завершилися зі `status: pass`; контрольна межа — 1e−8. QuTiP лише попереджає, що в ізольованому validation environment відсутній Matplotlib; перевірка динаміки від графіків не залежить.
- На попередньому checkpoint frontend мав **12/12 Vitest тестів**; актуальний прогін та bundle size наведені нижче.
- Реальний браузерний макет з усіма трьома панелями одночасно: 1280×720, 1920×1080 та 2560×1440 — горизонтального переповнення чи перетину панелей немає. Площа canvas від viewport: відповідно 91.9%, 94.6% і 96.0% (панелі плавають над сценою). Scene controls пройшли Orbit/Pan/Zoom/Fly/Focus/Reset; кліком вибрано спін C. Після короткої взаємодії з перетягуванням та масштабуванням UI показав 60 FPS у п’яти приблизно секундних зчитуваннях. Це миттєвий лічильник браузерного рендера, не контрольований середній FPS benchmark.
- Браузерний API smoke пройшов для підготовки стану, локального оператора, вимірювання/CHSH, фазового затухання, TFIM, Dynamic Receiver, Analyzer і окремого перегляду Hensen 2015/2016. UI зберіг і повторно завантажив JSON запис; JSON і CSV експортовані реальними download-подіями; descriptive comparison двох збережених записів успішно повернувся з API. Hensen 2015 показав 245 valid trials, Hensen 2016 — 300; джерельні файли лише перечитувалися. Локальний запис вимірювання створено в `results/ui_experiments/experiment_20261021T192415Z_b4609f4c.*`; receiver запис `experiment_20261021T192917Z_59c297f4.json` має 5,268,337 байтів і CSV — 2,737,265 байтів. Ці локальні UI smoke-записи ігноруються Git та не належать до Stage 5B locked експериментальних артефактів.
- Повторний save receiver запису виявив, що 2 MB HTTP request cap відхиляв повні trajectory results. Ліміт локального API піднято до **64 MiB** із явною 413 помилкою понад межу; повний 5.27 MB receiver запис після цього збережено й завантажено без обрізання.
- До/після SHA-256 звірка **19/19** файлів Hensen (`data/references`) і Stage 5B (`results/stage5b`) пройшла: змін 0, відсутніх файлів 0. Дані, preregistration, оригінальний аналіз Hensen і Stage 5B результати не редагувалися.
- High-confidence scan не знайшов секретів або сторонніх приватних абсолютних шляхів у перевірених source/docs; `.git`, віртуальні середовища, `node_modules`, build output, дослідницькі результати та вихідні дані були виключені зі сканування.

Це локальний release-readiness checkpoint, а не опублікований release: робоче дерево залишається змішаним і dirty; файл ліцензії та підтверджені авторські метадані відсутні. Не створювалися commit, tag чи публікація.

## Фінальне підтвердження, 2026-10-21

- Python: **185/185** тестів пройшли; повний запуск завершився `OK` за 27.477 s. У тому числі пройшли no-signaling, Hensen integrity/reanalysis, Stage 4 phase-damping, Stage 5A TFIM, Stage 5B statistics/storage/API та HTTP concurrency guard. Один одночасний memory-heavy POST приймається; інший отримав структурований `503 server_busy`.
- Frontend: **14/14** тестів пройшли; TypeScript перевірка та production build успішні. JS bundle — 1,202.67 kB (337.67 kB gzip): Vite лишає попередження щодо chunk >500 kB, але збірка успішна.
- Ізольовані наукові звірки завершилися `status: pass` при допуску 1e−8: QuTiP 5.3.0 найбільша різниця серед перевірених випадків — **9.94e−10**; QuSpin 1.0.1 + SciPy DOP853 — **1.01e−9**. Включені OBC, статичне поле, некомутуюча еволюція, позитивний локальний імпульс, дія на віддаленого передавача та межі відрізково-сталого поля.
- Windows clean-start launcher вибрав вільний loopback-порт **8135** у цьому запуску, перевірив `/api/health` і HTML до готовності. У браузері виконано вимірювання singlet через Python API (C≈1, Smax≈2.8284), збереження, повторне завантаження і виклик JSON та CSV export. Це користувацький локальний UI запис, окремий від історичних Stage 5B результатів.
- Жива камера змінила ракурс після drag. Точковий індикатор FPS у вузькому вбудованому viewport показував **51** під час перевірки; це instantaneous counter, не усереднений benchmark. Попередні п’ять коротких читань при wide viewport показували **60**.
- Версія `0.5.0` успішно зібрана в локальний wheel і встановлена в активне `.venv`; `importlib.metadata` тепер також повертає `0.5.0`. Перша ізольована спроба `pip install -e .` з build isolation не могла завантажити setuptools через недоступність PyPI; локальний build без мережі успішно перевірив пакет.
- Порівняння з передаудитним baseline: **19/19** файлів Hensen/Stage 5B мають ті самі SHA-256; жодної зміни чи зникнення не виявлено.
- Візуальні screenshots з трьома розмірами viewport і відкритими панелями залишаються в `outputs/orbital-lab-check/` попереднього UI аудиту; результати: 1280×720, 1920×1080 та 2560×1440 без перетину панелей і горизонтального overflow. У цьому запуску локальний app стартував і працював у вбудованому браузері; власний browser viewport був вузьким, тому він не замінює ті три resolution captures.
- `DEPENDENCY_AUDIT.md` підсумовує lockfile metadata й виявлену прогалину `webgl-constants` metadata (MIT текст є у включеному LICENSE). Це не замінює створення повного стороннього notice pack перед розповсюдженням.
- `git diff --check` пройшов. Змішане робоче дерево лишається незакоміченим; `v0.5.0` tag відсутній, remotes не задані, публікації не виконувалися. Публічний реліз усе ще потребує погодження авторства, ліцензії та дозволів на поширення даних/асетів.
